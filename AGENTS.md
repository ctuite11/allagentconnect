# Project rules

- All agent-facing DCMLS UI is gated by the single `DCMLS_SETTINGS_UI_ENABLED` flag; hiding it must preserve stored DCMLS fields and leave the consumer-host/backend behavior intact so launch restoration is reversible.
- All public and private Developer access is gated by the single `DEVELOPER_ACCESS_UI_ENABLED` flag; hiding it must preserve Developer accounts, memberships, projects, data, and implementation so launch restoration is reversible.

- On-screen listing addresses use `buildDisplayAddress` / `listingCardStreetHeading` from `src/lib/utils`; web and email formatters share `supabase/functions/_shared/addressFormatFixtures.json` so the website and emails format addresses the same way.
- First-publish social selections live on Add Listing and persist as listing defaults; the publish confirmation stays listing-only and later update choices remain one-off, keeping publishing concerns separated.
- Hot Sheet rules are LOCKED: connected-buyer, first-invite, Send-button label and status defaults/order come only from `src/lib/hotSheetRules.ts`, guarded by `src/lib/hotSheetRules.test.ts` and `filterStaleInviteTokens.test.ts`; changing a rule requires changing its test in the same change, because these decisions kept regressing when re-implemented inline.
- Contact creation from any screen goes through the `resolve_or_create_agent_contact` database function (`src/lib/agentContactResolver.ts`): it reuses this agent's existing contact, blocks another member's email, and never attaches Hot Sheets, so contact ownership is enforced server-side and stays separate from Hot Sheet membership. Verify with `supabase/tests/resolve_or_create_agent_contact.sql`.
- Hot-Sheet-only people ("Save to contacts? → No") are real contacts with `clients.hidden_from_contacts = true`, created via the resolver's `p_hidden`; agent-facing lists/pickers/counts filter them out, by-ID Hot Sheet/buyer flows don't, and only an explicit save promotes them (never invite acceptance), so Hot Sheet links always hold real UUIDs without overriding the agent's choice. Guarded by `src/lib/hiddenContacts.test.ts`.
- Communications Center property-type defaults come only from `src/lib/propertyTypeDefaults.ts` (guarded by its test): unconfigured agents get the default, saved non-empty choices are never overwritten, so every screen shows the same default.
- A listing leaves `draft` only through the `publish_listing(listing_id, operation_id)` database function, called solely from the "Yes, Publish Listing" click in `AddListing.tsx`. The `aaa_listings_guard_draft_publish` trigger rejects non-draft inserts and every other draft → non-draft update, and `listing_publish_audit` records each attempt. Guarded by `src/lib/draftPublishGuard.test.ts`. Why: a Draft (16 N Mead St) went live with no proof the confirmation was clicked.
- Agent Network directory visibility and Communications email eligibility are separate: hidden agents get core Communications emails (broadcasts, digests, broadcast re-sends) only when `agent_settings.comms_email_when_hidden` is true, via `includeCommsHiddenOptIn` in `_shared/verifiedAgentAudience.ts`. Why: the owner must stay hidden yet receive Comms emails without a blanket admin/hidden exception.
- Account-specific Communications geographic supplements belong only in the broadcast recipient adapter, gated by both canonical account ID and recipient email, using original unsplit criteria; never alter the shared matcher or other callers. Why: preserve other recipients and explicit county conflicts while isolating the approved correction.
- Hot Sheet type is explicit (`hot_sheets.sheet_type`: personal | buyer | NULL legacy). Personal sheets never get contacts, recipient batches or invites — enforced by DB triggers plus `process-hot-sheet`/`send-hot-sheet-invite` refusals and `canSheetSendToBuyers` in `hotSheetRules.ts`; NULL keeps legacy behavior and is never auto-reclassified. Why: an agent's own sheet sent an invitation because "no contact" was the only signal for Personal.
- Hot Sheet drafts are `hot_sheets.is_draft = true` rows: a trigger keeps them inactive with no contact, they refuse contacts/batches/invites, and they skip the buyer-need sync. Only `finalize_hot_sheet()` turns a draft (or a new sheet) into an active Hot Sheet, in one all-or-nothing step. Verify with `scripts/run-hot-sheet-draft-tests.sh` (a throwaway local database). Why: a partly saved sheet or a half-finished draft must never match listings, appear as a buyer need, or reach a buyer.
- Password-reset routing: `main.tsx` records a recovery-link landing in memory (`src/lib/authRecoveryLanding.ts`, tokens required) before the auth client strips the hash, and `AuthCallback` honours it; all reset emails return to `/auth/callback`, and `/password-reset` never writes account status. Why: the lazy callback page lost the hash and sent a reset link to the dashboard.
