# Project rules

- On-screen listing addresses use `buildDisplayAddress` / `listingCardStreetHeading` from `src/lib/utils`; web and email formatters share `supabase/functions/_shared/addressFormatFixtures.json` so the website and emails format addresses the same way.
- First-publish social selections live on Add Listing and persist as listing defaults; the publish confirmation stays listing-only and later update choices remain one-off, keeping publishing concerns separated.
- Hot Sheet rules are LOCKED: connected-buyer, first-invite, Send-button label and status defaults/order come only from `src/lib/hotSheetRules.ts`, guarded by `src/lib/hotSheetRules.test.ts` and `filterStaleInviteTokens.test.ts`; changing a rule requires changing its test in the same change, because these decisions kept regressing when re-implemented inline.
- Contact creation from any screen goes through the `resolve_or_create_agent_contact` database function (`src/lib/agentContactResolver.ts`): it reuses this agent's existing contact, blocks another member's email, and never attaches Hot Sheets, so contact ownership is enforced server-side and stays separate from Hot Sheet membership. Verify with `supabase/tests/resolve_or_create_agent_contact.sql`.
- Hot-Sheet-only people ("Save to contacts? → No") are real contacts with `clients.hidden_from_contacts = true`, created via the resolver's `p_hidden`; agent-facing lists/pickers/counts filter them out, by-ID Hot Sheet/buyer flows don't, and only an explicit save promotes them (never invite acceptance), so Hot Sheet links always hold real UUIDs without overriding the agent's choice. Guarded by `src/lib/hiddenContacts.test.ts`.
- Communications Center property-type defaults come only from `src/lib/propertyTypeDefaults.ts` (guarded by its test): unconfigured agents get the default, saved non-empty choices are never overwritten, so every screen shows the same default.
